What a valid competition TIFF must contain

The official competition specification requires predictions for the full region, on the organizer's template grid:

  • Single-band GeoTIFF.
  • Float32 pixel values.
  • EPSG:32611 (WGS 84 / UTM zone 11N) and the same resolution, bounds, shape, and geotransform as the sample submission.
  • Predictions in [0, 1] inside the evaluation footprint.
  • Outside the footprint, use the null/NaN representation accepted by the official format. Do not fill the outside mask with an undocumented sentinel.

Do not assume the grid dimensions or transform from a prior site's artifact. Read them from the current official sample-submission raster and compare every grid property exactly.

Source: DrivenData GEMS competition homepage (navigate to Problem Description for metric and format); CRS reference: EPSG:32611.

How to submit after the candidate gate is green

  1. Wait for a green release card. It must report a positive paired corridor-vs-no-corridor spatial holdout result, leakage checks, duplicate checks, file hash, and a passing exact-grid validator. A projection or a result against known catalogue lines alone is not enough to skip the project gate.
  2. Download the specifically named TIFF from this site's one-click button. At present there is no such file. Do not upload an old site artifact, a sample raster, or a zero-filled test file.
  3. Open the official GEMS competition on DrivenData and choose “Submit” → “Make new submission”. The contest form accepts one GeoTIFF or a ZIP containing one GeoTIFF.
  4. Choose the downloaded `.tif` in “File to submit”. Confirm its filename is the candidate named in the release card.
  5. Enter the exact unique submission name and short note shown with the candidate. The note should identify the hypothesis and key test, not imply a result that was not measured.
  6. Review and submit. Save the resulting organizer receipt. Only that receipt can confirm the organizer score for that exact submission.

About the range error

The reported portal error was: Predicted values must be in range [0, 1]. Its specific cause is unknown because neither the rejected file nor its submission receipt is in this checkout. The error cannot be diagnosed by looking at a different TIFF.

On the exact failed file, inspect the values after applying the sample-submission footprint mask. Check for raw scores that were not normalized, negative or greater-than-one values, infinities, NaNs inside the footprint, and large negative nodata sentinels that were accidentally copied into prediction cells. Separately check that outside-footprint cells use the documented null/NaN convention. Then reopen the written bytes and rerun the same validator the organizers specify.

Do not “fix” it by blindly clipping. Clipping can hide a nodata/footprint bug and changes the prediction distribution. Establish which pixels are inside the actual footprint, transform the model output deliberately, and record before/after statistics and the exact file hash.
