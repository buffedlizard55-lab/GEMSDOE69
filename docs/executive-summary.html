Executive summary — release decision first

No file is currently cleared. Do not upload a TIFF from submissions/; those files are retained only for audit. The home-page banner is generated by scripts/release_gate.py; it is the sole publication policy.

Required sequence before a future submission

  1. Preregister and generate: restore the exact integrity-pinned inputs and use the shared template's cached feature stack, holdout evaluator, and submission writer. A TIFF written during development is not automatically publishable.
  2. Validate exact bytes: re-read the artifact with the shared validator. It must be a single-band float32 GeoTIFF in EPSG:32611, 3730×3292, with transform (100, 0, 243350, 0, −100, 4508550), finite footprint values in [0,1], and the required outside-footprint behavior.
  3. Science gate: use untouched spatially blocked hide-and-recover data; withhold whole fault segments (not chunks) with at least a 3 px feature-context buffer; derive catalogue features only from visible faults and mask visible faults pixel-exactly. Score pooled DTI with α=0.2, β=0.8, and the 300 m triangular kernel. Require positive paired 95% bootstrap CIs against both the no-prior control and current lane-best; bind the holdout and protocol audit to the exact artifact SHA-256; run a feature-alone leakage canary for every named feature.
  4. Literal registry gate: compare the pre-placement surface and final dots against every available registry raster. Any rank correlation above 0.90 or any >70% 3-pixel dot overlap is duplicate-and-stop. Dense-support strata are diagnostics, not exemptions.
  5. Publish and submit: only if the banner becomes green, download the exact linked .tif, open DrivenData competition 306 → New submission, select it (or a ZIP with exactly one GeoTIFF), and paste the receipt note of at most 140 characters. A selector still decides whether to spend a weekly slot.

About the portal range error

Do not infer that a filename suffix alone makes a file safe. Re-run scripts/validate_submission.py <file> on the exact bytes and upload only the artifact explicitly linked by an OK TO DOWNLOAD banner.
