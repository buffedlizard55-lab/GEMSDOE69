2 · Steps to submit (once a gate-approved file exists)

  1. Register on DrivenData and accept the rules (S02, §3.1). Download the official training files from the data page into data/ (see data/README.md).
  2. Check the gate. Run python scripts/status.py. Do not upload unless it reports download_enabled: true and a receipt in docs/receipts/.
  3. Validate the file against the official grid: 
    python -m gems.validate_submission submission.tif --reference data/training_features.tif --json receipt.json
    All checks must pass. Exit code 0 means pass. The validator checks: single band, float32, EPSG:32611, 100 m, same shape and transform as the reference, finite values in [0, 1], and NaN only outside the footprint.
  4. Name it uniquely, for example gems69-<method>-<YYYYMMDD>-<hash8>. The name must not match any earlier submission.
  5. Write a note of 140 characters or fewer (the project limit; the form's own limit is not in the official pages we could read, so check it on the form). The form field is labelled “Note (optional) — a short comment to help you or your team tell submissions apart later”.
  6. Upload on the “New submission” page: choose the file under “File to submit”, add the note, submit. Check that the score appears on the page.
  7. Record it: add the receipt, the sha256 and the score (labelled ORGANIZER-CONFIRMED only when it comes from the submission page) to docs/receipts/.

3 · If you see “Predicted values must be in range [0, 1]”

The cause has not been found, because the failing file is not in this repository (IR-13). These are the causes the validator tests for:

  • a value above 1 or below 0 anywhere in the file;
  • a NoData sentinel (for example −3.4e38) written as a value, or NaN written inside the footprint;
  • a float64 file, or a file written with the wrong dtype;
  • a file on a different grid, so the footprint is misplaced.

To diagnose it, run the validator on the file that failed and send the receipt.

4 · What this project will not do

  • It will not offer a file that fails the gate.
  • It will not use owner-supplied GitHub mirrors of the competition data (IR-09).
  • It will not state a holdout score that has not been measured. Every number is labelled.
