## 2. What the metric rewards [OFFICIAL → DERIVED]

Official definitions [S01]: `TPw = Σ_g max_x p(x)k(d)`, `FPw = Σ_x p(x)[1 − max_g k(d)]`, `FNw = Σ_g [1 − max_x p(x)k(d)]`,
`k(d) = max(1 − d/300, 0)`, `DTI = TPw/(TPw + 0.2·FPw + 0.8·FNw)`.

Two consequences, both checked by tests in `tests/test_metric.py`:

* **(a) FNw = |G| − TPw.** Every truth pixel contributes exactly 1 to TPw+FNw. So
  `DTI = T / (0.2·T + 0.2·FP + 0.8·|G|)`, where T = TPw, FP = FPw, |G| = number of truth pixels.
  The truth set size |G| is a fixed denominator; the score is a weighted recall per unit of predicted mass.
* **(b) The truth side takes a max, the prediction side is weighted by distance.** Several dots near one truth pixel
  earn only the best one. A dot's false-positive cost is `p·(1 − m)`, where m = max over truth pixels of k(d).
  A dot on a truth pixel costs nothing; a dot 300 m away costs its full mass.

**Exact admission rule [DERIVED, tested].** Adding one unit-mass dot at pixel x that raises TPw by Δt and has
covering weight m = max_g k(d(x,g)) increases DTI iff

    Δt · (D − 0.2·T)  >  0.2 · T · (1 − m),        with D = T + 0.2·FP + 0.8·FN

(implemented as `gems.metric.dot_is_worth_adding`; agreement with full recomputation is tested on random rasters).

Worked threshold [DERIVED]: at DTI = 0.2778, the rule becomes `Δt/(1 − m) > 0.2·DTI/(1 − 0.2·DTI) = 0.0588`.
So at that score level, a dot is worth adding when its expected gain in truth coverage exceeds about 6% of its
false-positive cost. Dots that cover no truth within 300 m (m = 0 and Δt = 0) can never pass.

## 3. Why sparse, binary, catalogue-avoiding emission can score well [OPINION, consistent with §2]

* **Mass discipline.** 37,654 dots is 0.73% of the footprint. Under §2(a) each dot's cost enters the denominator only
  through 0.2·FP, so a few hundred dots that each cover new truth can beat a dense field that covers the same truth.
* **Catalogue avoidance.** A dot near a *mapped* fault is only useful if it also covers *unmapped* truth within 300 m.
  If the scorer does not mask catalogue pixels (IR-25, unverified), a dot on mapped faults far from new faults is
  pure FP. Removing catalogue-adjacent dots is therefore consistent with the metric, but only if the owner's
  estimate of how many catalogue-adjacent dots were FP is right. We have no measurement of that.
* **What we cannot say.** We cannot say that this design caused 0.2778 (no receipt), nor that the same design
  would beat 0.4275. The owner's own local instruments do not rank live scores well (their ρ = +0.14 on
  "catalogue-hidden" [OWNER-REPORT]).
